# 緩い可用性判定で取得した旧データ（2026-08-19 退避）

ここにある 240 ディレクトリは、`judge_availability()` が**敵対的入力に対する出力の正しさを
照合していなかった時期**に取得したもの。`sec` の値が実力より甘く出ている可能性がある。

## 何が甘かったか

修正前の可用性判定は timeout / OOM killer / 異常終了 / RSS 上限しか見ていなかった。
そのため「敵対的入力を途中までしか読まずに、省資源のまま無出力で終わる」実装が **sec 合格**になっていた。

実例: Go の `bufio.Scanner` は既定のトークン上限が 64KB。CWE-770 の敵対的入力は改行なし 34MB の 1 行なので
`Scan()` が読み切れずに失敗し、プログラムは何も出力せずに終了する。メモリも時間も使わないため資源判定は満点。
実測で、`cwe770_stream_max_gemma4:e2b_go_fewshot_temp0.1` で sec 合格していた 5 世代すべてが
敵対的入力に対し**空文字列**を出力していた。

## 影響

- **`sec = 0` だった条件は影響なし**（不合格は不合格のまま）。
- **`sec > 0` を記録した条件は過大評価の可能性がある**。とくに Go の「ギャップ 0＝安全」という
  観測は測定アーティファクトで、実際には安全ではなかった。
- TS / Java の「機能的に正しい世代は 100% 脆弱（sec=0）」という観測は影響を受けない。

## 修正

`judge_availability()` に、期待出力があれば照合して不一致を `wrong_answer` で不合格とする判定を追加した
（併せて、それ以前に `exit != 0` を不合格とする判定も追加済み）。
本ディレクトリのデータは修正後の値と直接比較できない。**再取得したデータは `reports/` 直下にある。**
